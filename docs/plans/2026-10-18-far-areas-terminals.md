## TODA research facts that bind the design (see .superpowers/research/toda-terminals-2026-10.md)
- No city roster of TODAs exists; Naga uses color-zoned special franchises. Far-zone tricycles (Panicuason, Carolina, Pacol, San Isidro, Cararayan, Balatas) are zone-bound shuttles between their centro and a junction (Ord 1998-103 Sec 6a). That supports: jeepney to the zone, then a zone tricycle; it does NOT support door-to-door tricycle from Centro.
- An Ateneo TODA terminal and TODAs at jeepney terminals are owner reports with no official source: store as evidence `owner_report_unverified`, never as fact. VISTODA/LAVISTODA (Langon to Ateneo via Vistansa; Centro Cararayan feeder; waiting areas T15, T16 unmapped) is the only official tricycle route touching Ateneo.
- Only one OSM tricycle terminal exists (T14 Balatas, 13.6318672, 123.1973306). Fare: PHP 15 minimum (Ord 2024-002); no special-trip fare in any ordinance (PHP 60-80 figures are unofficial).

## Interpretation (default; alternatives in Open questions)
1. Far areas = Cararayan (with San Isidro, the far end of R1), Pacol (R6), Carolina-Panicuason (R7). A trip with an end in a far area gets NO point-to-point tricycle and NO Recommended tricycle; the Recommended option is the best jeepney.
2. Exception: a tricycle option into a far area exists only when the start is within 300 m (street-graph walk) of a tricycle terminal on file that serves that zone (T14 toward Cararayan; TODA terminals later). It is never Recommended, fare unavailable, copy "Special trip - fare not fixed - confirm with the driver", evidence owner_report_unverified.
3. Access option: a start in the city proper whose street-graph walk to the best jeepney boarding point for the zone is over 600 m (or no such jeepney option exists) gets one extra option "Tricycle + Jeep Rn": tricycle (PHP 15 minimum, F03, city proper only) to the route's loading point on file, then walk, then the jeepney. The walk-to-jeepney option stays.
4. Tricycles run in the city proper only: no tricycle leg ends in a far zone except the special-trip exception. Padyak unchanged.
5. Centro-Del Rosario has 3+ vias: R2 via Magsaysay (the owner's "Magsaysay-Francia"; Francia is in no instrument: owner_report_unverified, as RN04), R3 via Roxas (Diversion), R4 via Panganiban. Each via that can serve the trip is shown. The via list is data so a 4th via is a data edit.

## Data model

- `header` {schemaVersion 1, preparedOn, roadSnapshot "naga-roads-2026-10-16.osm.json", reviewer}.
- `barangayAnchors`: the 27 barangay place nodes {osmNodeId, name} for nearest-node membership.
- `farZones`: FZ01 Cararayan [12717296950 Cararayan, 14084819763 San Isidro] routes R1; FZ02 Pacol [12717296941] routes R6, R7; FZ03 Carolina-Panicuason [12717296954 Carolina, 11112006649 Panicuason] routes R7. Evidence owner_report_unverified, source U03. (Exactly the 5 barangay nodes OSM tags place=village; all other barangays are quarter. No barangay outlines exist.)
- `routeBoarding`: R6 -> terminal T10, R7 -> T11 (OSM 2017 community), R1 -> {pathStart: "outbound"} (no Centro loading point on file; label "where R1 starts (route plan)"). Gaps (R2, R3, R5, R8) listed, not needed now.
- `viaGroups`: VG-CENTRO-DELROSARIO routes R2 "Magsaysay" (aliasNote "Locals may call it Francia (unconfirmed)"), R3 "Roxas (Diversion)", R4 "Panganiban"; evidence T12 note and Ord 2025-070.

- Validation test: every OSM node id exists in the road snapshot with the stated name and place tag; every terminal code is a seed terminal with a coordinate; route codes exist; zone node sets disjoint; each via group has 2+ routes; each routeBoarding terminal lies within 100 m of its route path (a failing link is dropped from the data, not loosened).
- TODA import (T2): new terminals T17+ (kind terminal, modes tricycle, coordinate only when the research has one) and sources RT25+ and U03 in the modes seed (same seed date, new hash = revised batch per ADR 010; migration 0010 source regex already allows RT25+ and U03); owner reviews TODA rows before decision "import". Terminals without coordinates are never planned.

## Planner rules (numbers)
- `zoneOf(point)`: nearest barangay anchor (haversine); far when that anchor belongs to a far zone.
- `tricycleOption` omitted when either end is far, except the special-trip exception above (`SPECIAL_TRIP_TERMINAL_WALK_M = 300`).
- Far-end walk cap 1,500 m (`FAR_END_WALK_CAP_M`) instead of 750 m; must-save-walking still applies.
- Access option when destination far, origin not, `W` = street-graph walk of the best-score jeepney option whose last ride is a route of the destination zone, `W > 600` (`ACCESS_TRICYCLE_MIN_WALK_M`) or none exists. Target loading point = the zone's published routeBoarding coordinate within 100 m of the variant path with the shortest tricycle street route from the origin. At most one access option; id `tri>{variantId}@{b}-{a}`, mode jeepney, rides 1. Tricycle leg ends in the city proper.
- Via groups: when 2+ routes of one group have a one-ride candidate after must-save-walking, the jeepney block = Pareto picks + best candidate of each via route; block budget = 6 - walk - access - tricycle - padyak; trim non-via extras first (worst score), then vias by score; a label on a dropped option is dropped, not moved.
- Order: walk, jeepneys by score, access, tricycle, padyak. Ruling (e) amends (d): with a far end the Recommended option is the best jeepney, else the access option, else none (zero options: walk card unlabelled with the far note). Non-far trips unchanged (tricycle Recommended at 500 m or more).
