# Plan: maps core (increment 1, part A)

Date: 2026-10-15 · Branch: `feat/maps-core` (based on PR #5 `feat/landing-and-phone-gate`)
Spec: `docs/spec/` (F-A1 Home map, F-A2 Location and origin, S1 Home, §3.11, §5.9). Design: the ParaNaga Design System canvas (Home, Search, PlaceDetail, Walk, Components); extracted brief at `.superpowers/sdd/map-design-brief.md`.

Goal: a phone home map that is **locked to Naga City**, shows the user's **real GPS position honestly** (accuracy-aware), and lets anyone — including people **outside Naga City** — set a **start and destination by pinning on the map** or using their location. Trip results are out of scope: with both points set, the app shows the honest "no verified commute yet" state.

## Global Constraints

- **Stack:** Next.js 16.4 App Router with Cache Components, React 19, strict TypeScript, Tailwind v4 tokens in `src/app/globals.css`. **Before writing Next-specific code, read the relevant guide in `node_modules/next/dist/docs/`** (this Next version differs from training data; see `AGENTS.md`).
- **Maps: React-Leaflet + Leaflet raster tiles** (user decision; supersedes the spec's MapLibre). Leaflet touches `window`, so it loads **client-only** (a client component that `next/dynamic`-imports the Leaflet component with `ssr: false`). Import `leaflet/dist/leaflet.css` once.
- **Layering** (enforced by `pnpm check:boundaries`): `src/domain/**` is pure TypeScript — no React, Next, Leaflet, `window`, or I/O; `src/client/**` holds hooks/browser code; `src/ui/**` holds components; client and ui never import `src/server/**`.
- **Naga City boundary:** OpenStreetMap relation **3084673** ("Naga City"), stored at `data/geo/naga-city-boundary.geojson` (one Feature, Polygon, 1,269 points). Bounding box: lat **13.6023285–13.6743613**, lng **123.1751748–123.3764733**. License: **ODbL 1.0 — © OpenStreetMap contributors**; keep the provenance properties in the file.
- **Map lock:** `maxBounds` = the boundary bbox padded by **0.01°** on every side; `maxBoundsViscosity: 1.0`; `minZoom: 12`; `maxZoom: 19`; initial view centre **Plaza Rizal [13.6233869, 123.1846726]** at zoom **15**. Everything outside the city polygon is dimmed with an inverse-polygon mask (fill `#0F1E3D`, opacity **0.28** light / **0.45** dark), and the city outline is drawn (stroke `#0B7A75`, weight 2, no fill).
- **GPS policy (Jev decision, strict, p=0.99):** `PRECISE_M = 30`, `APPROXIMATE_M = 100`, `STALE_MS = 30_000`. ≤30 m = precise ("You are here"); 30–100 m = approximate (show "± N m" chip and the accuracy circle); >100 m = coarse — **never used automatically as the trip start**; the user confirms by pinning. `watchPosition` options: `{ enableHighAccuracy: true, maximumAge: 0, timeout: 20_000 }`. Location is requested **only after a user tap**, never on page load. Stop watching on unmount, on "stop", and while `document.visibilityState === "hidden"` (resume when visible if it was active). **Coordinates never leave the device** in this increment (no fetch, no storage beyond React state).
- **Outside Naga City:** a fix outside the polygon gets status `outside_city`. The map **does not pan or zoom to it** (stays locked); the sheet shows: "You're outside Naga City. Pin your starting point in Naga, or search for a place." with a "Choose start on map" action. GPS is never used as the start in that case.
- **Pinning:** "Choose on map" enters a crosshair mode: a fixed centre pin over the map, the user pans, then confirms "Set start here" / "Set destination here". Confirm is **disabled** while the centre is outside the polygon, with the hint "Move the pin inside Naga City". Points are always validated with the same point-in-polygon function.
- **Honesty:** with start and destination set, show both pins and the card **"No verified commute yet for this trip"** with the line "We're still checking routes and stops on the street. Trip options appear here once a route is verified." **Never draw a line between the two pins** and never show fares, times or routes.
- **Tiles:** `NEXT_PUBLIC_TILE_URL` and `NEXT_PUBLIC_TILE_ATTRIBUTION`. Production provider is **MapTiler** (Jev decision, p=0.89), e.g. `https://api.maptiler.com/maps/streets-v2/256/{z}/{x}/{y}.png?key=…` with attribution `© MapTiler © OpenStreetMap contributors`. When unset: outside production use `https://tile.openstreetmap.org/{z}/{x}/{y}.png` with `© OpenStreetMap contributors` (dev/test only — Jev p=0.94); **in production with no URL, render no basemap** (boundary, mask and pins still work) and show the small notice "Map background unavailable". Attribution is always visible (bottom-right, design's strip style).
- **Design:** follow `.superpowers/sdd/map-design-brief.md` for sizes, colors, radii, copy and dark-mode tokens; glass controls (rgba white 0.62 + blur), 44×44 px minimum touch targets, teal `#0B7A75` (dark `#2BB5AE`) location dot with a pulse that stops under `prefers-reduced-motion` (also: no `flyTo` animation then — jump instead).
- **Accessibility:** every control is a real `<button>`/`<a>` with an accessible name; state changes announced via an `aria-live="polite"` region; the map container has `role="region"` and `aria-label="Map of Naga City"`.
- **Tests:** Vitest for domain and hooks (hooks under a `jsdom` environment with `@testing-library/react`); Playwright e2e with `context.grantPermissions(['geolocation'])` + `setGeolocation`, and **tile requests aborted** in e2e so tests never hit tile servers. Existing suites must stay green (`pnpm verify`, `pnpm test:e2e`).
- **Commits:** one or more per task, conventional-commit messages, each ending with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never commit `.env.local` or secrets.

### Task 2: Location-fix quality rules (pure)

Files: `src/domain/geo/location-fix.ts`, `tests/unit/location-fix.test.ts`.

Build:
- `type LocationFix = { lat: number; lng: number; accuracy: number; timestamp: number; heading?: number | null; speed?: number | null }`.
- Constants `PRECISE_M = 30`, `APPROXIMATE_M = 100`, `STALE_MS = 30_000`.
- `fixQuality(fix): "precise" | "approximate" | "coarse"` (≤30 precise, ≤100 approximate, else coarse; non-finite or negative accuracy → coarse).
- `isStale(fix, now)`: `now - fix.timestamp > STALE_MS`.
- `pickBetterFix(current | null, next, now)`: returns `next` when there is no current, current is stale, `next.accuracy <= current.accuracy`, or `next` is newer by >10 s and `next.accuracy <= current.accuracy * 1.5`; otherwise keeps `current` (prevents a coarse network fix from replacing a good GPS fix).
- `assessFix(fix, now)`: `{ quality, stale, insideCity (via isInsideNaga), usableAsStart }` where `usableAsStart = quality !== "coarse" && !stale && insideCity`.

Tests (write first): threshold boundaries 30/30.01/100/100.01; NaN/negative accuracy → coarse; staleness at exactly 30 000 ms vs 30 001; `pickBetterFix` table of cases; `usableAsStart` false outside Naga even when precise; fast-check property: `pickBetterFix` never returns a fix with worse accuracy than `current` unless current is stale or `next` is newer by >10 s within the 1.5× allowance.

### Task 3: `useGeolocation` hook (client)

Files: `src/client/geo/use-geolocation.ts`, `tests/unit/use-geolocation.test.tsx`, `vitest.config.ts` (allow `.test.tsx` and a per-file `// @vitest-environment jsdom`), dev deps `jsdom`, `@testing-library/react`.

Build `useGeolocation()` returning `{ state, fix, assessment, start, stop }`:
- `state`: `"idle" | "requesting" | "watching" | "denied" | "unavailable" | "timeout" | "unsupported" | "insecure"` (`insecure` when `window.isSecureContext` is false; `unsupported` when `navigator.geolocation` is missing).
- `start()` (call only from a user gesture): calls `navigator.geolocation.watchPosition(success, error, { enableHighAccuracy: true, maximumAge: 0, timeout: 20_000 })`; each success runs `pickBetterFix`; `assessment = assessFix(fix, Date.now())`. Error codes: 1 → `denied`, 2 → `unavailable`, 3 → `timeout` (keep watching on timeout if a fix already exists).
- `stop()` and unmount call `clearWatch`. While `document.visibilityState === "hidden"`, clear the watch; on `visible`, resume only if it was active.
- Re-assess staleness every 5 s while watching (timer cleared on stop/unmount).
- No network, no storage.

Tests (write first, jsdom, mocked `navigator.geolocation`): never calls `watchPosition` before `start()`; options exactly as above; denied/unavailable/timeout mapping; a coarse fix after a precise one is ignored; `stop` and unmount clear the watch; hidden → clearWatch, visible → watch resumes; insecure context → `insecure` without calling geolocation.
